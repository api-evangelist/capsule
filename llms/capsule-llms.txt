# Capsule

> Capsule is a CRM and project-management platform for small and mid-sized
> businesses, operated by Zestia Ltd. The Capsule v2 REST API exposes parties
> (contacts and companies), opportunities, projects, tasks, entries, tracks
> and the settings behind them - pipelines, milestones, boards, stages, tags
> and custom fields - with REST Hooks webhooks for event-driven integration
> and a first-party read-only MCP server for AI assistants.

Auth: Authorization: Bearer {token} - personal access token, or an OAuth 2.0

Rate limit: 4,000 requests per hour per Capsule user. Watch
X-RateLimit-Limit / X-RateLimit-Remaining / X-RateLimit-Reset; 429 on

No idempotency mechanism exists: a retried POST creates a duplicate record.

## Agent surfaces
- [Capsule MCP Server](https://zestia.github.io/capsule-mcp-scala/): first-party, Apache-2.0, 49 read-only tools
- Runs LOCALLY over stdio: `docker run -i --rm -e CAPSULE_API_TOKEN=... ghcr.io/zestia/capsule-mcp-scala:latest`
- There is NO hosted/remote MCP endpoint. An agent cannot reach Capsule over MCP without a human installing Docker first.
- Private beta, Growth plan and above; request access from Integrations inside a Capsule account
- No A2A agent card is served on any Capsule host (probed 2026-09-05)
- mcp/capsule-tool-crosswalk.yml maps each MCP tool to the REST operation behind it

## Events
- REST Hooks: 19 events across party, kase (project), opportunity, task and user
- Subscribe with POST /api/v2/resthooks; max 20 subscriptions per account; OAuth applications only
- Deliveries retry 5 times over ~36 minutes, then the hook is unsubscribed
- No signature verification is published for webhook deliveries
